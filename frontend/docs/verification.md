# Next.js 변환 검증

2026-10-31 · 저장소의 Next.js 16.4.3 / React 19.3.0 / TypeScript 구성을 사용했다.

## 사용자 흐름

첫 화면 → 체형·상품군 → TPO → 추구미·태그 → 샘플 추천 서비스 → 응답 검증 → 결과 → 아이템·수정 → 옷장 저장·복원. 실제 추천 서버 연결은 사용자가 후속 작업으로 분리했다.

## 자동 검증

- `npm run typecheck`: TypeScript strict 타입 검사 통과.
- `npm run lint`: ESLint 및 Next.js·React 규칙 통과.
- `npm test`: 16개 테스트 통과. 기존 입력·추천·수정·저장 로직과 잘못된 응답·취소·시간 초과·null 복구를 유지했고, SSR 초기 스냅샷 분리, 추천 당시 조건과 세션 복원, 화면 이동 시 오래된 요청 취소와 빠른 오류 응답 보존을 추가했다.
- `npm run build`: App Router 7개 제품 경로 생성과 프로덕션 빌드 통과. `/picks/[id]`는 서버에서 비동기 매개변수를 읽는다.
- 저장소의 Next.js·React 의존성 버전은 변경하지 않았다. `npm ci`에서 기존 잠금 파일의 의존성에 대해 moderate 16건이 보고됐으며 강제 업데이트는 수행하지 않았다.

## 실제 브라우저

프로덕션 서버 `http://127.0.0.1:3000`에서 직접 조작했다.

| 경계 | 결과 | 증거 |
| --- | --- | --- |
| 페이지 렌더링 | 통과 | 루트 및 6개 후속 경로 표시, 브라우저 hydration 오류 없음 |
| 입력 → 상태 | 통과 | 상체 웨이브·하체 스트레이트, 발표, 미니멀, 태그 선택이 요약과 결과에 반영 |
| 태그 제한 | 통과 | 3개 이후 네 번째 선택 비활성, 선택 해제 가능 |
| 서비스 → 결과 | 통과 | 샘플 3코디, 각 4개 상품과 2열 배치 |
| 수정 → 결과 | 통과 | 스커트 변경, 상품·코멘트 갱신, 체형·TPO·추구미 유지 |
| 저장 → 복원 | 통과 | 담기·취소·분류·개수·메모, 새로고침 후 프로필과 옷장 복원 |
| 오류 → 재시도 | 통과 | `?demo=error` 후 다시 시도하여 코디 3개 복구 |
| 빈 결과 | 통과 | `?demo=empty`에서 조건 수정 안내 |
| 키보드 | 통과 | 라디오 방향키와 본문 바로가기 포커스 |
| 모바일 | 통과 | 390px에서 입력부터 상세까지 이동, 대표 화면의 가로 넘침 없음 |
| 실제 API → 서버 데이터 | 후속 | 서버 주소·계약 확정 후 연결. 현재 검증 범위가 아님 |

화면 캡처는 `docs/qa/`에 있다. 브라우저 전체 페이지 캡처가 일부 화면에서 실패해 문서화된 viewport 캡처로 확인했다. 캡처 한 장이 화면 전체 스크롤 영역을 나타내지는 않는다. 스크롤을 이동하며 입력·저장·수정 액션을 별도로 조작했고 DOM의 가로 너비도 확인했다.

디자인 탐지와 이미지 메타데이터 검사를 수행했다. 기존 디자인 문서의 대표 글자 크기 목록과 세부 반응형 CSS 사이의 차이는 advisory로 보고됐으며, 기술 스택 변환 범위에서는 검수한 크기를 유지했다. 이미지 3개 모두 생성 프롬프트 메타데이터가 있다.

## React 전환 검토

`dangerouslySetInnerHTML`이나 전역 DOM 렌더링 없이 JSX 컴포넌트로 구현했다. 제어형 입력, 안정적인 key, 페이지별 서버 메타데이터, Next Link, 브라우저 저장소용 `useSyncExternalStore`를 사용한다. 서버 스냅샷은 고정된 공통 초기값이며 브라우저 데이터는 서버의 공유 상태로 저장하지 않는다. 비동기 작업은 취소 신호와 요청 버전으로 오래된 완료를 무시한다. 사용자 상품 링크는 검증 후 렌더링한다.

검증 한계: 실제 API·인증·실시간 상품·기기 간 동기화, 실제 모바일 기기와 보조 기술, 다른 브라우저 엔진은 검증하지 않았다. 상품 이미지·가격·코멘트는 샘플로 표시한다.
