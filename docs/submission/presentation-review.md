# 첨부 발표자료 점검

대상: 「1. 해피엔딩팀 발표 자료 PPT.pdf」. 기준: 참가자 가이드 3~6쪽. 원본 PDF는 이번 작업에서 수정하지 않았습니다.

## 분량·필수 항목

표지 포함 11쪽, 본문 10쪽으로 분량 요건에 맞습니다. 문제·사용자(본문 1), 기능(2~3), AI·직접 개발(4~5), 스택(6), 역할(7), 외부 자원(8), 효과·확장(9~10)의 일곱 항목을 모두 포함합니다. 외부 자원 표도 요구한 네 열 형식을 사용합니다.

## 제출 전 보완할 내용

1. **본문 8쪽: 외부 CI 참고 출처 추가.** 코드에 `gomin-diary/gomin`의 마이그레이션 워크플로 참고·변형 이력이 있습니다. [외부 자원 표](external-resources.md)의 해당 행을 반영하고 라이선스·이용 권한을 팀이 확인합니다.
2. **사전 보유 코드 여부 재확인.** 발표본은 '해당 없음'이지만, 저장소만으로 개회식 이전 작성·보유 여부를 증명할 수 없습니다. CI 참고 이력을 포함해 팀이 사실관계를 확정합니다.
3. **구현과 검증 수치를 구분.** 상품 1,024개·이미지 URL 6,876개·정제 속성 1,024개 이관과 체크섬 대조를 수행했습니다. 추천 정확도·시간 단축·전체 성공률 실험을 수행한 것으로 쓰지 않습니다.
4. **추천 개수 표현.** 최초 최대 3개이며 조건에 따라 적게 반환할 수 있습니다. '우선 1개와 대안 2개'는 화면 구성 설명으로 사용하고 별도 점수 모델이 세 코디의 우열을 보장한다고 설명하지 않습니다.
5. **설명 검증의 현재 동작.** AI 수정 요청 후에도 근거 없는 설명만 남으면 해당 설명을 제외하고 상품 ID·상품군·필수 조건·예산은 다시 검증합니다. 모든 오류를 단순 재시도로 해결한다고 표현하지 않습니다.
6. **공개 주제 대조.** 제공된 가이드에는 당일 공개 주제 내용이 없습니다. 주제 적합성은 실제 공지와 별도 대조합니다.

## 예상 질문에 대한 답변 근거

| 질문 | 답변 핵심 | 근거 |
|---|---|---|
| AI가 DB를 직접 조회하나? | 서버가 후보를 추출하고 AI에는 JSON 후보만 전달 | `backend/app/ai/candidates.py`, `client.py` |
| 에이전트가 계속 질문하나? | 요청별 2단계 흐름. 불명확할 때 질문 반환, 대화 루프 없음 | `backend/app/ai/service.py` |
| 자체 개발은 무엇인가? | 수집·정제·후보·검증·수정 제약·회원 옷장 | [외부 자원 구분](external-resources.md) |
| 왜 같은 조건에서 실패했나? | 확인되지 않은 설명 속성으로 검증 실패한 사례 재현·보완 | [AI 기록](../ai-recommendations.md) |
| null 패턴은 무지인가? | 미확인이다. 후보에는 허용하지만 무지라고 설명하지 않음 | `ai/candidates.py`, `prompts.py` |
| 실제 옷이 맞는다고 보장하나? | 체형은 스타일 지침. 실측 보존과 착용 적합성 보장은 다름 | [AI 흐름](../ai-recommendations.md) |
| 다음 개발은? | 속성 검수·평가 지표·추가 플랫폼. 모두 향후 계획 | 발표 본문 9~10쪽 |

문서 요건 점검은 운영진의 접수·심사 판정을 대신하지 않습니다. 발표자료가 가이드를 충족해도 영상·소스가 누락되면 제출물 전체가 완성된 것은 아닙니다.
