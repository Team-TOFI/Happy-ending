# 현재 DB 기반 AI 추천

기본 모델은 COPA의 OpenAI 호환 `/chat/completions`를 사용하는 `gpt-5.4-mini`입니다. 서버의 Bearer 키로 호출하며 실제 요청 본문은 `model`·`messages`입니다. 프롬프트에 JSON Schema를 넣고 응답은 Pydantic 및 서버 규칙으로 검증합니다.

## 처리 순서

| 단계 | 주체 | 입력·출력 |
|---|---|---|
| 카탈로그 로드 | 서버 | 정제 지문·버전이 최신인 상품. 프론트 요청은 성별·공용 여부·가격 확인 |
| 필수 조건 해석 | AI | TPO, 상세 요청·태그, 명시 조건, 예산 → 조건 JSON 또는 최대 3개 질문 |
| 후보 구성 | 서버 | 필수·제외·가격 조건 적용, 소분류 균형 추출, 상품군별 최대 24개 |
| 코디 선택 | AI | 체형·TPO·추구미·후보 속성·실측 → 후보 상품 ID와 근거 속성 |
| 결과 검증 | 서버 | ID, 중복, 상품군, 총예산, 수정 유지 상품 및 근거 확인 → 원본 상품 정보 결합 |

AI가 직접 SQL을 만들거나 DB·웹·이미지에 접근하지 않습니다. 고정 50/30/20 가중합은 기본 AI 추천에 사용하지 않으며 비교용 `/recommendations/rules`에만 남아 있습니다.

기본 프론트 추천은 상의·하의·신발·가방을 구성하고 최대 3코디를 반환합니다. 수정은 최대 1코디이며 요청에 따라 가방을 아우터로 바꿀 수 있습니다. 상세 AI API에서 `categories`를 명시하면 해당 상품군을 필수로 검사합니다. 미지정 시 필터 전 DB에 있던 상의·하의·신발을 필수로 확정합니다.

## 속성 정책

- 원문 출처·근거가 있는 `pending`과 `approved`를 후보와 필수 조건에 사용할 수 있습니다. pending은 미검수 안내를 유지합니다.
- null을 무지·검정·정핏으로 추정하지 않습니다. rejected·근거 없는 값은 확인된 속성으로 쓰지 않습니다.
- 현재 사용자 정책상 패턴 null은 패턴 require/exclude/known 조건에서도 후보 제외 사유가 아닙니다. 특정 패턴 조건을 충족했다고 설명하지 않으며 미확인 안내를 붙입니다.
- 조문에서는 서버도 빨강 제외·색상 확인을 적용합니다. 확인된 금지 속성은 계속 제외합니다.
- 일반 체형 지침·추구미는 선택 선호이며 무조건 필수 필터로 만들지 않도록 지시합니다. 치수·사이즈가 실제로 맞는다고 보장하지 않습니다.

## 반복 호출과 실패 처리

매 요청마다 조건 해석·선택을 실행하며 캐시·고정 시드·대화 기억을 사용하지 않습니다. 같은 조건이어도 코디와 개수는 달라질 수 있습니다. 질문이 반환될 수 있지만 스스로 질문을 이어가는 에이전트 루프는 없습니다.

각 단계의 잘못된 응답에는 최대 한 번 수정 요청합니다. 상품 ID·필수 조건 검증은 재시도에도 유지합니다. 설명에만 확인되지 않은 속성이 반복되면 그 설명을 제외한 뒤 같은 상품 검증을 수행합니다. 잘못된 설명을 사실로 반환하거나 무조건 다른 상품으로 대체하지 않습니다. 설명 근거가 남지 않으면 일반적인 구성 문구를 사용합니다.

2026-11-01 점검에서 같은 조문 조건 3회 중 1회, 같은 남성 일상 조건 3회 중 1회가 설명 속성 검증으로 실패했습니다. 로컬 추적에서는 특정 상품의 확인되지 않은 `silhouette=WIDE`를 AI가 두 번 반복했습니다. 수정 후 실패 응답 재생이 성공했고, 실제 AI로 두 조건을 각각 3번 호출해 6회 모두 결과를 반환했습니다. 제한된 표본이며 전체 조건의 성공률을 뜻하지 않습니다.

프론트 대기 시간과 외부 API 지연, 응답 형식·선택 실패, 데이터 부족은 서로 다른 실패입니다. 남아 있는 간헐 오류를 모두 해결했다고 가정하지 않습니다. 사용자 표시와 백엔드 로그를 함께 확인합니다.

## 구현 위치

- `backend/app/ai/client.py`: COPA HTTP 호출·응답 형식
- `schemas.py`, `prompts.py`: 조건·선택 계약과 지침
- `candidates.py`: 서버 조건·후보 제한
- `validation.py`: 상품·근거 검증
- `service.py`: 해석·선택·수정 요청 흐름
- `backend/app/tofi/`: 프론트 변환·기존 코디 재확인·수정 범위

설정과 API 예시는 [백엔드 README](../backend/README.md)에 있습니다.
